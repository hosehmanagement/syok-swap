# H3 engine (openjutsu Simple swap + Check mask on Modal)

**Status: deployed and live-tested on Modal** (Modal app `syok-swap-h3`). First live test, 21 Nov 2026, through
`test-h3.yml`: a 6 s clip at 480p swapped successfully; the mask check took about 17 minutes including a cold start on an
L4, the swap about 3 minutes on an L40S. This is the only engine in this repo (the old Wan2.2-Animate app was removed).

| File | What it is |
|---|---|
| `h3_engine.py` | Pure Python: openjutsu's `lib/simple.ts` + `lib/clips.ts` ported, job folder / `meta.json` rules, ComfyUI history parsing |
| `h3_app.py` | Modal: image (ComfyUI + 5 packs), two Volumes, the ComfyUI process per call, local entry points |
| `workflows/openjutsu/*.api.json` | openjutsu's exports (Simple, Check mask, Fix faces), byte-identical copies (MIT, see `LICENSE` there) |
| `comfy_extra_models.yaml` | registers the `ultralytics` model folder on the models Volume (Fix faces detectors) |
| `tests/test_h3_engine.py` | unit tests, no GPU, no network |
| `h3_api.py` | The web API (plain FastAPI, no Modal import), served by `h3_app.web` behind Modal's proxy token |
| `tests/test_h3_api.py` | Every route through FastAPI's TestClient with fake GPU steps, incl. the territory gate |

## Flow

```
modal run h3_app.py::fetch                             # once, see "Model files" below
modal run h3_app.py::new   --video v.mp4 --photo p.png --consent yes --margin normal --start 0 --length 6 --seed 0 --resolution 480p
modal run h3_app.py::check --job <id>                  # small GPU, SAM 3.1 only -> check.mp4 (cyan = regenerated)
modal run h3_app.py::swap  --job <id>                  # the paid step -> h3.mp4
modal run h3_app.py::fixfaces --job <id> --mode photo  # OPTIONAL paid step on the finished swap -> faces.mp4
modal run h3_app.py::status --job <id>
```

Inputs: source video, new-person photo, margin (tight 20 / normal 40 / loose 60 px), start and length (seconds, length 0 =
to the end, 2 s minimum, 30 s maximum per job), seed (0 to 4294967295), resolution (480p, 576p, 736p, 768p, 1080p, or
`WIDTHxHEIGHT` from 256 to 2048, rounded to 32). Also available with openjutsu's defaults: role, target (`person`), hat fix
(off), No lip-sync (off), motion reference (512), clip length (6 s).

Job states in `meta.json` (job folder helpers from `texture_service.py`: `new_job`, `read_meta`, `write_meta`, `set_stage`):
`check: idle -> queued -> running -> ready | error`, `swap: idle -> queued -> generating -> done | error`,
`faces: idle -> queued -> generating -> done | error` (with `attempts`, `mode`, `message`).
The swap needs a ready check first, and refuses to start while running or once done (no double billing). Fix faces needs
`swap.state == done` and follows the same rules. Jobs made before Fix faces existed read as `faces: idle`.

**Resume:** ComfyUI's output folder is the job's `comfy_out/` on the `syok-h3-jobs` Volume, where the Context Loop keeps a
checkpoint per finished clip. Running `swap` again on the same job after an error resumes from the last finished clip
(`swap.resume = true`, `swap.attempts` counts runs). Settings are frozen at upload, so a resume always matches.

## Web API (h3_api.py, served by `h3_app.web`)

The live test above ran through the `modal run` entry points, not through these routes; the routes are covered by the
TestClient tests in `tests/test_h3_api.py`. `build_h3_app(root, spawn_check, spawn_swap, spawn_weights, weights_state, ...)`
takes the GPU steps as plain functions; `h3_app.web` passes `check_job.spawn`, `swap_job.spawn`, `fetch_models.spawn({})` and
`h3_engine.weights_state(MODELS)`, reloads both Volumes before each request and commits the jobs Volume after each write.
The endpoint is `@modal.asgi_app(requires_proxy_auth=True)`: it answers only to the user's Modal proxy token.

| Route | What it does |
|---|---|
| `GET /health` | `{"ok", "app": "syok-swap-h3", "version": 1, "engine": "minimax-h3", "weights": "ready\|downloading\|missing", "label": "MiniMax H3", "territory": "US, EU, UK and South Korea are excluded", "limits": {"video_mb": 60, "photo_mb": 8, "seconds": 30, "keep_days": 3}, "resolutions", "margins"}` |
| `POST /setup` | starts `fetch_models` when files are missing -> `{"weights": "downloading\|ready"}` |
| `POST /swap` | multipart `video`, `photo`, `consent=yes`, `territory=yes`, `margin`, `resolution`, `start`, `length` -> `{"job", "estimate"}`. Creates the job, records `h3_territory: "yes"`, `country` and a `territory_record` (h3_territory.make_territory_record) in `meta.json`, and starts the mask check at once |
| `GET /status/{job}` | `h3_engine.status(...)` (check / swap stages, request, clips, expires_at) plus `estimate` |
| `GET /mask/{job}` | `check.mp4` (`video/mp4`) once `check.state == ready`, else 409 |
| `POST /generate/{job}` | the PAID step: `h3_engine.start_swap` + `swap_job`. 409 without a ready check, while running, or once done; after an error it resumes (`{"state": "queued", "resume": true}`) |
| `GET /result/{job}` | `h3.mp4` (`video/mp4`), 409 until done |
| `POST /fixfaces/{job}` | OPTIONAL paid step, JSON `{"mode": "photo"\|"mouth"}` (empty body or no mode = `photo`) -> `{"state": "queued"}`. Territory gate first (451, before the body is read). 400 for another mode or a body that is not a JSON object; 409 unless `swap.state == done`, while Fix faces is queued or running, or once it is done; after an error it may be started again (it runs again from the start, `faces.resume = true`). 409 while the Fix faces model files are not on the Volume (the request starts their download when they are missing). 500 if `faces_job` cannot be spawned (the stage is then `error`, so it can be started again) |
| `GET /faces/{job}` | `faces.mp4` (`video/mp4`, file name `syok-h3-faces-<job>.mp4`), 409 until `faces.state == done` |
| `DELETE /job/{job}` | `{"deleted": true}`; the swap and the Fix faces result go with the job |

Errors are `{"error": "<plain text>"}` with the status from `JobError` (400 bad input, 404 unknown job, 409 wrong stage or
not an H3 job, 422 no `consent=yes`, 500 a GPU step could not be spawned: the stage is then marked failed, never left queued).
`POST /swap` also answers 409 while the model files are not ready.

`estimate` is approximate and has **no money figure** (none was measured for H3): `check_minutes` 17 (one cold-start run on
an L4) and, for 480p only, `swap_minutes` scaled from one run (6 s in about 3 minutes on an L40S); other resolutions get
`swap_minutes: null`.

`weights` is `ready` when no model file is missing (`h3_engine.models_missing`), `downloading` while `fetch_models` holds its
start flag (`.h3-fetch-started` in the models Volume, cleared when it ends or fails, ignored after 4 h 5 min), else `missing`.

### Territory: the router adds the header

- The country comes **only** from the `X-Syok-Country` request header. **The Syok router Worker adds it** from Cloudflare's
  `request.cf.country` on every H3 route and strips any copy the browser sent; the Modal endpoint answers only to the proxy
  token, which only the router holds. A form field (or query) of any similar name is **never** read.
- `h3_territory.check_country` decides, **fail closed**: a missing or empty header, anything not two letters, `XX`, `T1`,
  and US, GB, KR and the 27 EU codes -> **451** `{"error": "territory", "message": "MiniMax H3 is not available where you
  are (US, EU, UK, South Korea)."}`. Nothing is stored or started.
- Checked on `POST /swap` (the header **and** the tick box `territory=yes`, exact value), `POST /generate/{job}` (the H3
  run), `POST /fixfaces/{job}` (the H3 face run) and `POST /setup` (the H3 model download). The territory check comes
  first, before consent (422), the body and the model check.
- Not checked on `/health`, `/status`, `/mask`, `/result`, `/faces` and `DELETE /job`, so a user can always read and
  delete their own job here (the router still checks the country on every route).
- This is a safeguard, not legal compliance (IP-based, defeated by a VPN): see `docs/H3_TERRITORY.md`.

## Fix faces (optional, opt-in)

The H3 swap keeps the motion and background but the face can drift from the photo. openjutsu's **Fix faces** works on the
FINISHED swap video (`h3.mp4`) with the same photo: H3-FaceRefine tracks the photo's face over the video (InsightFace picks
that person out when there are several) and crops it to 512x512; H3 Face Fix Chunks splits the crops into independent
chunks (6.5 s, overlapping by at least 1 s, 24 fps); H3 redraws only the SAM face mask of each chunk with the photo as
reference; H3 Face Fix Join crossfades the chunks and H3 Face Stitch pastes the face back. Only the face matching the photo
changes; faces taller than 1/5 of the frame are left alone (`skip_faces_above: 0.2`).

- **Modes:** `photo` = **Match the photo** (closest likeness; H3 makes up the expressions and mouth). `mouth` = **Follow the
  mouth** (keeps the video's expressions and mouth movements, slightly less likeness). `h3_engine.prune_face` ports
  openjutsu `lib/face.ts`: Match the photo deletes exactly the "Blurred face (follow the mouth)" node, the chunk node's
  `follow_mouth` input and the reference node's `ref_videos.ref_video_0`; both modes set the seed (the job's seed) and the
  chunk length (6.5 s). The export was written on Windows, so the detector names get forward slashes
  (`bbox/face_yolov8m.pt`): ComfyUI on Linux lists them that way and refuses any other spelling.
- **Sound:** the fixed video gets the soundtrack of the video it reads (the swap result, which carries the original
  soundtrack) through `VHS_VideoCombine`, so it is re-encoded with the video, as in the swap; H3's edit keeps the source
  audio (`preserve source audio`).
- **No checkpoints:** the chunks are not chained through the Context Loop, so starting it again after an error runs it
  again from the start (and is billed again).
- **GPU:** `faces_job` uses `SYOK_H3_FACES_GPU`, default the swap's GPU (`L40S`, 64 GB RAM): it loads the same H3 model,
  32B text encoder and VAEs as the swap, on 512x512 crops, so the GPU that ran the live swap is the one known to fit. Time
  cap `SYOK_H3_FACES_MINUTES` (default 120). `max_containers=1`.
- **Time:** **not measured on Modal**, so the estimate has no `faces_minutes`. Upstream data only (openjutsu README, not
  ours): a 17 s video at 768p (4 chunks) took about 28 minutes on an RTX 4060 Ti, including model loading.
- **Model files** (in `MODEL_FILES` for stage `faces`, plus the six H3 files the swap already uses), fetched by the same
  `fetch` / `POST /setup` step, which skips files already there. `POST /fixfaces` starts that download when the face files
  are missing and answers 409 until they are there; they never hold up a swap (`weights` in `/health` still means the swap
  and check files only).

## Region

`SYOK_H3_REGION` (unset by default = no pin). Example: `SYOK_H3_REGION=ap modal deploy h3_app.py`.

- Modal's region guide lists the Asia-Pacific names `ap` (broad), `ap-northeast`, `ap-southeast`, `ap-south`,
  `ap-melbourne` (narrow) and `jp`, `au`. A pinned region costs 1.15x (broad) or 1.75x (narrow) of the base price.
- **Not verified: whether the account's Modal plan may pin a region.** The current guide does not say. Modal's 2024 launch
  post said Team (CPU only) and Enterprise, on request. So no region is pinned by default.
- A narrow region also has fewer GPUs, so a run may wait longer for one.

## Model files

The seven files the two workflows load are listed in `h3_engine.MODEL_FILES`, with their download sources in
`MODEL_SOURCES`. Verified on 21 Nov 2026 by listing each Hugging Face repo (names and sizes match openjutsu's table; the
files were not downloaded or hash-checked): `Comfy-Org/MiniMax-H3` (H3 base model 21.0 GB, video VAE, audio VAE),
`Merserk/MiniMax-H3-INT4-ConvRot` (Qwen3-VL 32B INT4, 15.0 GB), `Comfy-Org/Qwen3-VL` (8B INT8, 9.4 GB),
`Comfy-Org/sam3.1` (SAM 3.1, 1.7 GB) and `Kijai/MiniMax-H3-experimental` (DMAD 4-step LoRA). About 51 GB in total.
To use a different source, pass `--sources`:

```json
{"minimax_h3_ref2va_pruned_int8_convrot.safetensors": {"repo_id": "owner/name", "path_in_repo": "...", "revision": "..."}}
```

The download runs inside Modal (`huggingface_hub`) straight into the `syok-h3-models` Volume. If a repo is gated, create a
Modal Secret with `HF_TOKEN` and deploy with `SYOK_H3_HF_SECRET=<secret name>`. No token is stored in this repo.
